# CW Trainer 固件设计

日期：2026-08-25
状态：设计定稿，待写实现计划
灰阶原型：`docs/design/cw-trainer-prototype.html`（320×240，可点通全部页面与状态）

## 1. 产品定义

> 帮助**想上 CW 通联但还不敢开口的业余无线电爱好者**，通过**随身盒子上的听写训练和电键反馈**，完成**从零到能独立完成一次标准 CW QSO**。

目标用户是新手到中级，不是提速工具，也不是电码百科。

核心场景：碎片时间听写一课；上电台前抄几个呼号热身；接电键练手；看一眼自己的进度。

### MVP（本 spec 范围）

1. Koch 听写训练：Farnsworth 间距、课前新字母预告、每组即时判分、90% 以上解锁下一课、进度存 NVS。
2. 呼号抄收 / 模拟 QSO：4 选 1 选择题，干扰项按易混字符生成。
3. 电键：触摸屏双桨（预留外接口）、Iambic A/B/直键、侧音、实时解码显示。

### 明确不做（增强项，另开 spec）

时序分析图、错字热力图、进度曲线、速度阶梯、CW 报时、RGB 指示、SD 卡文本库、蓝牙侧音、联网对练、WiFi。

### 形态

**独立固件** `firmware/cw-trainer`，不与 FMO 伴侣共存。完全离线，无 WiFi、无蓝牙。

## 2. 用户流程

### A. Koch 一课

```
开机 → 主页（Koch 第 N 课 · 上次 x%）→ 继续练习
  → 课前预告：显示并播放本课新字母 3 遍（巩固练习跳过此页）
  → 播放 5 字符一组 → 键盘输入 → 立即判分（0.8s）→ 下一组，共 10 组
  → 结算：正确率、错字、达标提示；达标时提供"进入下一课"，不自动切换
```

不设"选课/选速度/选音调"步骤，全部沿用上次设置。中途退出需确认，本轮不计入。

### B. 呼号抄收 / 模拟 QSO

```
主页 → 呼号抄收 → 播放一个呼号 → 4 选 1 → 判分 → 下一个，共 10 个 → 结算
```

呼号字符集 = 当前 Koch 已解锁字符集∩（字母+数字）；不足以生成呼号时用全集并提示"建议先练 Koch"。
模拟 QSO 播放整句 `<本机呼号> DE <对方呼号> <对方呼号> K UR RST <RST> <RST> BK`（对方回应本机的定向呼叫），用户填两项（对方呼号、RST），各 4 选 1。
对方呼号播两遍：既符合实际通联习惯，也给新手两次抄收机会。开头的本机呼号是用户已知内容，不增加难度，
但在一串莫尔斯里认出自己的呼号本身就是最该练的听力技能，等于顺带练到了。

### C. 电键

```
主页 → 电键 → 上半区解码文本 + 当前字符点划序列，下半区触摸桨 → 退出即走
```

### 全局

- 首次启动无向导；主页显示"第 1 课 · K M · 未开始"。
- 设置为低频入口（主页顶栏 ⚙）。
- 电源：沿用现有电池监测 / 低电量逻辑；练习与电键页不灭屏，主页闲置 2 分钟灭屏（触摸唤醒）。**[已搁置]** 电池监测/百分比/<15% 提示已实现，但"沿用现有低电量逻辑"里的自动关机部分未实现，见下方状态清单同一行的标注和 `firmware/cw-trainer/README.md` 里的说明。
- NVS 损坏或版本不符 → 视为首次启动，主页顶部一次性提示"进度已重置"。

## 3. 页面与主任务

| 页面 | 主任务 | 次要 | 低频 |
|---|---|---|---|
| 主页 | 一键继续 Koch | 呼号抄收、模拟 QSO、电键 | 设置（顶栏 ⚙） |
| 课前预告 | 听+看新字母 | 再听一遍 / 开始练习 | — |
| 听写练习（三模式共用） | 听后输入答案 | 重播、进度 n/10 | 退出 |
| 结算 | 看正确率与错字 | 再来一轮 / 进下一课 | 返回主页 |
| 电键 | 按桨发报看解码 | WPM 显示、清屏 | 退出 |
| 设置 | 改速度/音调 | 电键、呼号、亮度 | Koch 课次、恢复出厂 |

## 4. 线框（320×240 横屏）

以原型为准，摘要：

- **主页**：顶栏 时间 | 电量 | ⚙（图标大小即可）；左 200px Koch 大卡片（课次、已解锁字母、上次正确率、"继续练习 >"），右 120px 三个入口各 ~70px。
- **课前预告**：大字新字母 + 点划序列，"正在播放 n/3"，底部 [再听一遍][开始练习]。
- **听写练习 Koch**：≤12 键时左右分栏（左：提示/输入格/重播，右 150px 4 列键盘）；>12 键时顶部一行输入区（提示 + 输入格 + 重播）+ 全宽键盘，20 键 6 列（≈53×42），40 键 8 列（≈40×34）。播放中键盘与重播灰显。判分在输入区原地覆盖 0.8s：正确显示答案；错误显示用户输入、错位标记 `^`、正确答案。
- **呼号抄收**：顶部提示 + 重播，下方 2×2 选项各 160×85。
- **模拟 QSO**：提示行，"对方呼号"4 选 1 一行，"RST"4 选 1 一行，右下 [提交]。
- **结算**：左大字百分比 + n/10，右错字列表 + 达标行，底部 [进入第 N+1 课][再来一轮][返回主页]（未达标 / 非 Koch 模式无第一个按钮）。
- **电键**：顶栏 < | WPM | [清屏]；解码区 2 行等宽字体 + 居中当前字符序列；下半 120px 双桨（直键模式合并为一块；外接输入时改为"外接电键已就绪"+ 两个随按键高亮的指示块）。
- **设置**：左 60px 三个分组 tab（音频 / 电键 / 常规），右侧列表每行 42px。
  - 音频：字符速度、有效速度、音调、音量
  - 电键：电键输入（触摸屏 / 外接口）、电键类型（直键 / Iambic A / Iambic B）、桨键左右对调
  - 常规：我的呼号、Koch 课次、屏幕亮度、恢复出厂设置、版本
- **数值调整页**：[−] 大字当前值 [+]，音频组带 [试听]（播放 "PARIS"）。呼号编辑用 4×9 全字符键盘。
- **选项页**：单选列表，点选即返回。
- **恢复出厂**：说明 + [取消][确认清除]。

## 6. 技术架构

### 6.1 工程

`firmware/cw-trainer`，ESP-IDF + LVGL，从 `fmo-companion` 复制以下模块基本不改：`battery_monitor`、`app_power_save`、`gpio_ctrl`、`ui_async`、`components/lv_porting`、`components/lvgl*`、字体。删除 `wifi_manager`、`audio_ws`、`bt_audio`、`audio_output`、`event_parser`、`station_parser`、`qth_lookup`、`esp_websocket_client` 依赖。`app_settings` 重写为本项目字段。屏幕横屏（LVGL 旋转 90°，触摸坐标随之校准）。

### 6.2 模块划分

```
morse_table   字符 ↔ 点划序列表（字母、数字、标点、prosign）。纯函数，可主机单测。
morse_timing  WPM / Farnsworth → 点、划、字符间、词间时长（ms）。纯函数。
tone_gen      低延迟侧音：直接驱动 I2S 内置 DAC（GPIO26 + GPIO4 使能），
              小 DMA 缓冲（≤10ms），正弦 + 5ms 起落包络，接口 tone_on()/tone_off()/set_freq/set_volume。
cw_player     把文本按时序发成 tone_on/off 事件（用 esp_timer），用于所有播放场景；
              回调 on_char_start（预告页高亮）、on_done。
keyer         电键状态机：输入 dit/dah/straight 电平 → 输出 tone_on/off + 元素事件。
              模式：直键 / Iambic A / Iambic B。10ms tick，纯逻辑可单测。
key_input     把触摸桨（LVGL 事件）或外接口 GPIO（IO22/IO27，内部上拉、去抖 10ms）
              统一为 keyer 的输入电平。外接口 MVP 只留接口与设置项，驱动实现在硬件接上后补。
cw_decoder    根据元素时长流实时解码为字符：自适应点划阈值，字符间/词间判定。纯逻辑可单测。
koch_engine   课程表（40 字符标准 Koch 顺序，39 课）、生成 5 字符组、评分、达标判定、进度读写。
callsign_gen  按字符集生成合法格式呼号，生成 3 个易混干扰项（S/H、U/V、E/I、N/M、5/S、0/O 等替换）。
trainer       练习会话状态机（播放中 → 输入 → 判分 → 下一组 → 结算），三模式共用，
              驱动 cw_player 与 UI。
app_settings  NVS blob（版本号 + 字段），见 6.3。
ui_*          LVGL 页面：ui_home / ui_preview / ui_practice / ui_result / ui_keyer / ui_settings。
              UI 只做显示与事件转发，不含业务逻辑。
```

### 6.3 持久化（NVS）

```c
typedef struct {
    uint32_t version;
    uint8_t  char_wpm;        // 5..40，默认 20
    uint8_t  eff_wpm;         // 5..char_wpm，默认 8
    uint16_t tone_hz;         // 400..1000，默认 600
    uint8_t  volume;          // 0..100，默认 70
    uint8_t  key_input;       // 0 触摸屏 1 外接口
    uint8_t  keyer_mode;      // 0 直键 1 Iambic A 2 Iambic B
    uint8_t  paddle_swap;
    char     callsign[12];    // 默认 BI8SYN
    uint8_t  koch_lesson;     // 1..39（40 字符 Koch 序列，第 1 课 K M，之后每课加 1 字符，共 39 课）
    uint8_t  koch_last_pct[41]; // 下标 = 课次，每课最近一次正确率，0xFF 表示未练
    uint8_t  brightness;
} cw_settings_t;
```

版本不符或 CRC 错 → 写默认值并置"进度重置"标志。

### 6.4 数据流

- 播放：trainer → cw_player → tone_gen；cw_player 事件 → UI（LVGL 线程经 ui_async）。
- 电键：触摸/GPIO → key_input → keyer → tone_gen；keyer 元素事件 → cw_decoder → UI。
- keyer 与 tone_gen 运行在独立高优先级任务，侧音延迟目标 <15ms。

### 6.5 错误处理

- DAC/I2S 初始化失败：记录标志，UI 各页顶部提示，其余功能照常。
- NVS 写失败：日志 + 本次运行内存生效，主页不提示（避免打扰）。
- 触摸多点/抖动：桨键区按 LVGL PRESSED/RELEASED 事件，去抖由 keyer tick 天然完成。

## 7. 测试策略

- **主机单测**（纯 C，不依赖 IDF）：`morse_table`、`morse_timing`、`keyer`（给定输入电平序列断言输出元素序列，覆盖 Iambic A/B 差异与 squeeze）、`cw_decoder`（喂标准时序 + ±20% 抖动断言解码）、`koch_engine`（升课判定、分组生成字符集）、`callsign_gen`（格式合法、干扰项互异）。
- **设备验证**：侧音延迟用示波器/录音测；三条主场景走通；状态清单逐项目视检查。

## 8. 实施阶段
