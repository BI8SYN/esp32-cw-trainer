本次三件事：

1. 外接电键真正能用——换到 GPIO18 / GPIO23，并去掉「一根线空闲即为低就把电键钉死」的风险。
2. 触摸桨与外接口**并联**，删掉「电键输入」这个二选一设置；按外接口时屏幕上对应的块高亮。
3. 联网对练里 wire 11 的显示名从「QSO 陪练」改成「AI 陪练」。
4. 主页顶栏的电量可以关掉——有人根本没接电池（见 §9，本条在前三条实施完成后追加）。

## 1. 为什么现在能做外接电键了

代码其实早就写好了一半：`key_input.c` 里有 `CW_KEY_INPUT_EXT` 分支、10ms 去抖、
启动自检，`core/keyer.c` 里直键 / Iambic A / Iambic B 三种模式都实现了。卡住的
一直是**引脚**。

`BOARD_KEY_DAH_GPIO` 原来是 GPIO27，实测空闲电平就是低的——选中外接口的那一刻起
「划桨一直按着」，与操作者是否碰过键无关。`board_config.h` 里为此写了 33 行注释，
推测原因是板子把这条网络设计成扩展 SPI 的片选输出、上面有比内部弱上拉更强的外部
偏置。**这个推测是错的**：真实原因是本机改装时 GPIO27 上接了蜂鸣器。这条注释必须
改成事实，否则下一个人还会照着错误的线索去量板子。

### 1.1 四个候选引脚的核对

LCD 占 12/13/14/15/2/21，触摸占 25/32/33/36/39，都不冲突。剩下可用的是 18 / 19 /
23 / 35：

| GPIO | 位置 | 内部上拉 | 板上有无器件驱动它 | 结论 |
|---|---|---|---|---|
| **18**（SD_SCK） | CN3 | 有 | 无——SD 设计里是**输出**，卡座那端只接收 | **选中** |
| **23**（SD_MOSI） | CN3 | 有 | 无——同上，是输出 | **选中** |
| 19（SD_MISO） | CN3 | 有 | 有——SD 设计里是**输入**，插了 TF 卡时卡片的 DO 会驱动它 | 次选 |
| 35 | CN4 | **无**（34~39 是输入专用段，无内部上下拉） | 无 | 需外接 10k 上拉 |

判据是**方向**：18 和 23 在板子原本的 SD 方案里是 ESP32 往外送的信号，卡座那侧只是
接收端，板上没有任何东西会跟输入抢电平。这正是 GPIO27 踩过的坑的反面——27 出问题
就是因为线上另有器件在拉。

CN3 只有 5 根信号线、没有电源和地，地从 CN4（丝印 `GND / IO35 / 3.3V`）引一根到
面包板。18/23 用内部上拉、按键直接对地，**面包板上一个电阻都不用加**。

GPIO35 有意留空：它是唯一不碰 SD 总线的引脚，以后真要做 SD 卡功能时它还能顶上。

### 1.2 board_config.h

```c
/* 外接电键。CN3 丝印 IO18(SCK) / IO23(MOSI)；地从 CN4 引。
 * 低电平有效、内部上拉，面包板上按键直接对地即可，不需要外接电阻。
 *
 * 为什么是这两根：板子把 18/23 规划成 SD 的 SCK/MOSI，也就是 ESP32 往外送的
 * 输出，卡座那侧只是接收端——板上没有任何器件会跟输入抢电平。19(SD_MISO) 是
 * 回读线，插了 TF 卡时卡片的 DO 会驱动它。35 在 CN4 上，但属于 34~39 输入专用
 * 段，没有内部上下拉，必须外接电阻。27 本机已接蜂鸣器（见 docs/hardware.md
 * 「本机改装」），不能再当输入。 */
#define BOARD_KEY_DIT_GPIO  GPIO_NUM_18
#define BOARD_KEY_DAH_GPIO  GPIO_NUM_23
```

### 1.3 接口形态：面包板按键与 3.5mm TRS

CN3 / CN4 是 1.25mm 卧式座子（和 CN2/CN5 同款），不是 2.54 排针——进板子的唯一通路
是一条 1.25mm 5P 端子线，两种接法都要用它。

**面包板（当前阶段）**：CN3 脚2(IO18) 和 脚4(IO23) 各接一个轻触开关到地，地从 CN4
脚1 引。CN3 的丝印顺序是 `IO27(CS) IO18(SCK) IO19(MISO) IO23(MOSI) IO22`。

**3.5mm TRS（成品电键）**：Tip = 点、Ring = 划、Sleeve = 地，这是 Elecraft / Yaesu /
Icom / Kenwood / Begali 一致的行业约定。它和本设计的引脚天然对齐：

| TRS 触点 | 接到 | 引脚 |
|---|---|---|
| Tip | CN3 脚2 | IO18（dit） |
| Ring | CN3 脚4 | IO23（dah） |
| Sleeve | CN4 脚1 | GND |

两种接法**在固件里完全不可区分**，不需要任何代码分支——按键对地和电键触点对地是同
一件事。

不加任何元件：内部上拉（约 45kΩ）+ 固件 10ms 去抖已经够。若担心外接线缆的干扰，
每根信号线**串** 100Ω~470Ω 即可，对时序无影响。

**绝不要在信号线与地之间加 100nF 滤波电容。** 45kΩ 上拉配 100nF 的时间常数是 4.5ms，
上升沿要好几毫秒才爬过高电平门限；30 WPM 一个点才 40ms，这会直接毁掉手法分析页赖以
工作的边沿时刻。真要滤，1nF 封顶（τ=45µs）。

### 1.4 直键的单声道插头：门闩的第二个用武之地

成品**直键**配的多是 TS 单声道插头。单声道插头插进立体声母座时，**套筒会把 Ring 和
Sleeve 短接**——插上的那一刻划线就永久接地了。

这个场景**由 §2.3 的 armed 门闩自动正确处理**：被短接的划线从头到尾都是低电平，
永远不会开闸，直接被忽略，点线照常工作。配合「电键类型 = 直键」（`keyer_tick()` 只
看 `dit_in`）就能直接用。

**记在这里是为了防止将来有人认为门闩是过度设计而删掉它。** 它挡的不只是本机 GPIO27
上的蜂鸣器那一次意外——「一根线恒为低」是外接 3.5mm 口的**常规**工况，每一次插直键
都会发生。

## 2. 双输入并联

### 2.1 合并规则

删掉 `cw_settings_t.key_input` 这个二选一，触摸桨和外接口**同时生效**，按位或：

```
e[i]  = 去抖(外接线 i) && armed[i]
in[i] = touch[i] || e[i]              ← 屏幕上第 i 块的按下状态
a, b  = in[0], in[1]
if (paddle_swap) 交换 a, b
dit, dah = a, b
```

`in[]` 取在**对调之前**，所以它天然对应屏幕上左右两块，与对调开关无关——这正是
UI 高亮需要的量。`paddle_swap` 仍然只在这一处应用一次，触摸和外接不会得到相反的
对调结果（这条不变，是现有代码已经做对的事）。

### 2.2 对调作用于两边，标签跟着换，但直键除外

「桨键左右对调」名字和语义都不动：触摸和外接**一起**对调。理由是左撇子用触摸屏时
同样希望左块是划——这不是只属于物理电键的需求。

但屏幕上两块的**标签必须跟着换**：开对调后左块印「划」、右块印「点」。否则左块印着
「点」却发出划，标签就在撒谎。

**直键不参与对调**（实施时补的判断，原文没考虑到）。单个触点没有「左右」可言，
而真按对调处理的话，屏幕上那一整条走的是 `touch[0]`，会被换到 dah 上，`keyer_tick()`
的直键分支只看 `dit_in`——结果是开了对调之后屏幕直键按了完全没反应。外接直键同理
固定留在点线（IO18 / TRS 的 Tip），这也正是 TS 单声道插头的接法。
`read_inputs()` 和 `ui_keyer_paddles()` 两处都要用同一个判断。

### 2.3 armed 门闩：一根线必须先松开过一次

这是本次唯一新增的安全机制，**必须有**。外接口从「选中才采样」变成**永远采样**：
一根空闲即为低的线会把电键彻底钉死，而且连触摸也一起失效（合并是或，被钉死的那一
路永远为真）。GPIO27 上已经发生过一次，不能指望它不再发生。

> **规则：每根线必须先被观察到「松开」过一次，才被允许说话。**
>
> - 每根线一个 `armed` 标志。
> - `key_input_start()` 里原始采样一次，用它**给去抖状态播种**
>   （`s_ext_last[i] = s_ext_stable[i] = raw`），这样去抖值从第一拍起就有效。
> - `armed[i]` 由**去抖后**的值驱动：每读到一次「未按下」就置 true。
> - `armed == false` 的线一律按「没按下」处理。

门闩判据统一用去抖值、不用原始值：原始值上一个方向相反的毛刺就足以给一根真正卡住
的线开闸，而开闸之后去抖值仍然是「按下」，键照样被钉死——等于门闩白设。去抖要求
连续两拍一致，毛刺过不去。

于是：开机就是低电平的线永远不会被采纳；页面进入时你正好按着键，松一下就好了。

**不加超时**（不做「按住超过 N 秒即判定卡住」）。内部上拉下拔掉线读到的是高电平，
不会假卡住，超时挡不住任何真实故障；反过来它会误伤真正的长按。这条规则的收益为零、
代价为真，不要它。

### 2.4 卡住的可见反馈

静默忽略一根坏线，表现是「按了没反应且毫无线索」，和 GPIO27 那次一样难查。所以要
说出来：

```c
/* 位掩码：bit0 = 点线被门闩挡住，bit1 = 划线被门闩挡住。 */
uint8_t key_input_ext_blocked(void);
```

电键页在 `key_input_start()` 之后读一次，若非零就把提示写进**点划行**（`s_seq`），
文案带上引脚号，例如：

```
外接划线(IO23)一直按下
```

**必须写点划行，不能写解码文本区。** 解码文本区 `s_text` 用的是 `UI_FONT_MID`
（font28），只有 96 个 ASCII 字形、不含中文，中文会静默渲染成一排豆腐块——`ui_keyer.c`
里建触摸桨那段注释已经为同一件事踩过坑。点划行 `s_seq` 用的是 `UI_FONT_CN`
（font20，3888 字形），是本页唯一能显示中文且进页面时为空的位置。带上 `IO23` 这样的
引脚号是有意的：开了「桨键左右对调」之后「点线/划线」指的是哪根物理线会含糊，引脚号
不会。

清除时机：提示一直留到**你第一次碰键**为止，之后点划行交还本职。`poll()` 里加一个
标志位：

```c
static bool s_warn;   /* 卡住提示是否还占着点划行 */

/* poll() 开头 */
const char *p = key_input_pattern();
if (s_warn) {
    if (!*p && !key_input_key_down()) return;   /* 还没动过键，让提示留着 */
    s_warn = false;                              /* 一按键就交还给点划行 */
}
```

**不用 `ui_notice()`**：电键页顶栏之下的纵向预算已经排满——解码 74 + 13 间距 +
点划 26 + 13 间距 + 电键 84 = 210，只剩 2px。再插一条 28px 的通知条会把整块内容下推
28px，而电键块是贴着屏幕底边固定的（`py = 240 - UI_PADDLE_H`），结果点划行会压进
电键块 15px。这条隐患在音频异常时（`tone_gen_is_ok()` 为假）就已经存在，属于既有
问题，**本次不动，仅在此记录**——它和外接电键无关，顺手改会把这次的改动面摊大。

## 3. 屏幕联动

### 3.1 `ui_keyer_paddles()` 收编布局分支

签名保持 `(parent, y, h, out[2])`，`out` 允许传 NULL。

> **实施时更正：** 原文说把 `out[2]` 砍掉，那是错的——对练页要用这两个对象做
> 「未连线时禁用电键」（`ui_net.c:266`）。参数留着，只有电键页和手法页改传 NULL。

它自己按 `keyer_mode` 和 `paddle_swap` 决定长什么样：

- 直键 → 一块整宽「直键（按住）」，事件接 paddle 0
- Iambic A/B → 两块 160 宽，标签按 `paddle_swap` 决定谁是点谁是划

**这修掉一个现存 bug**：电键页自己写了三条布局分支，而对练页（`ui_net.c:760`）和
手法页（`ui_fist.c`）无条件铺两块桨——直键模式下这两页会显示两块桨，但右边那块根本
不接线（`keyer_tick()` 在直键分支只看 `dit_in`）。收进一处，一次修三页。

同时**整个消灭** `ui_keyer.c` 里跨页面 static `s_pad[]` 的 use-after-free 隐患：
现在光是解释怎么绕开它就花了 10 行注释（每条分支各自负责清零自己不写的下标），
改完之后 `s_pad[]` 不再需要存在。

### 3.2 高亮

`ui_keyer_paddles()` 内部建一个 50ms 的 `lv_timer` 做高亮刷新，挂在 pad[0] 的
`LV_EVENT_DELETE` 上自毁。三个页面各自的 poll 一行都不用改，高亮自动就有了。

数据源：

```c
/* 屏幕上第 i 块（0=左，1=右）当前是否按下，触摸与外接合并后、对调之前。 */
bool key_input_paddle_down(int i);
```

画法：`make_btn()` 已经给 `LV_STATE_PRESSED` 配了 `UI_GRAY_DOWN`，触摸按下的高亮
本来就有；外接走 `LV_PART_MAIN` 默认态的 `bg_color`，同色，两条路径视觉一致。

**必须缓存上次写入的值、只在变化时写。** `lv_obj_set_style_bg_color()` 会触发样式
刷新和重绘，20Hz 无脑重写会让电键块持续闪烁。

`iambic_a_does_not_send_memorized` 两条，squeeze 后同时松开、B 多发一个反向元素而
A 不发，正是这个分野。写 spec 时没打开这个文件看。

### 7.2 把合并逻辑抽出来才能测

「触摸 / 外接并联 × armed 门闩 × 对调」这三者的交互是本次最容易出错的地方，但它现在
和 GPIO 读取、FreeRTOS 任务缠在一起，主机侧单测碰不到。抽成一个无副作用的纯函数
放进 `core/`：

```c
/* core/key_merge.h */
typedef struct { bool dit, dah; bool in[2]; } key_merge_out_t;

/* touch[2]   触摸桨当前状态
 * ext_raw[2] 外接线去抖后的状态（true = 按下）
 * armed[2]   门闩，false 表示这根线还没被观察到松开过
 * swap       桨键左右对调
 * 出参 in[2] 是屏幕上第 i 块的按下状态（合并后、对调前），给 UI 高亮用。 */
void key_merge(const bool touch[2], const bool ext_raw[2],
               const bool armed[2], bool swap, key_merge_out_t *out);
```

`key_input.c` 只负责采样、去抖、维护 `armed[]`，然后调用它。沿用仓库里 `core/` 放
纯逻辑、`test/` 放主机侧单测的既有分工。

要覆盖的组合：只触摸 / 只外接 / 两者同时 / 门闩未开时外接线为真被忽略 / 对调开关对
`dit,dah` 生效但对 `in[]` 不生效。

### 7.3 真机验收（单测覆盖不到）

以下三条主机侧单测一条都摸不着，**必须上真机**：

1. armed 门闩：开机时把外接按键按住不放进电键页，确认不会一直发音；松开后恢复正常。
2. 高亮不闪：按住外接点键 10 秒，电键块颜色稳定，不闪烁。
3. 直键模式下三个页面（电键 / 对练 / 手法）都只显示一块整宽的键。

## 8. 不做的事

- **不加「按住超过 N 秒判定卡住」的超时**，理由见 2.3。
- **不修电键页 `ui_notice()` 与点划行的重叠**（音频异常时才出现），理由见 2.4。
- **不改 `CW_NET_QSO_WIRE` 宏名**，理由见第 5 节。
- **不改 GPIO35 的用途**，留给以后的 SD 卡方案。
- **不动 `TRAINER_MODE_QSO` / 主页的「模拟 QSO」**——那是离线练习模式，与联网对练的
  陪练机器人是两回事，这次改名只针对后者。

## 9. 电量显示开关（追加需求）

前三条实施并真机验证之后追加。**动机很实际：有人根本没接电池**，顶栏那个电池图标
和百分比对他们只是噪音，而且读数还是假的（没有电池时 ADC 量到的是分压网络上的
残留电平，不是任何有意义的电量）。

### 9.1 一项三选一，不是两个开关

原始需求描述的是「显示电量开关 + 是否显示百分比」两个开关。做成一项三选一：

| 值 | 显示 |
|---|---|
| `CW_BATT_HIDE` | 什么都不显示 |
| `CW_BATT_ICON` | 只有电池图标 |
| `CW_BATT_NUM` | 图标 + 百分比数字（出厂默认，也是 v3 之前唯一的行为） |

两个独立开关会造出「百分比开着但电量关了」这种无效组合，要么把第二项置灰、要么允许
一个没有任何效果的开关存在，两条路都不如一项三选一干净。菜单里也只占一行。
`IT_CHOICE` 类型现成就有。

菜单文案用「图标+数字」而不是「图标和数字」：`fmt_val()` 的调用处缓冲是 `char b[16]`，
五个中文正好 15 字节 + NUL = 16，**零余量**——以后谁多加一个字就会在 UTF-8 字符
中间截断，屏幕上出现半个乱码字。加号版 13 字节，留得住。

### 9.2 设置升到 version 3，顺便删掉那个死字节

`§4.1` 当时为了避开升版本，把 `key_input` 留成了 `reserved_key_input` 死字节。那条
推理是错的（见 §4.1 的更正框），而且既然现在必须升版本了，保留它的理由也不存在了。

v3 的做法：**删掉 `key_input`、末尾加 `battery_show`**，一减一加恰好抵消，结构体仍然
是 68 字节。v1 / v2 / v3 三者 `sizeof` 全相同，所以 `cw_settings_init()` 里**必须靠
version 字段分辨**——这正是原来 v1 分支已经在做的事，照抄一份给 v2 即可。

两个历史布局快照加 `_Static_assert(sizeof(...) == 68)` 钉死：它们描述的是**已经写在
别人设备 NVS 里的字节**，谁"顺手整理"一下就会把老配置读错位，静态断言让它当场编译
失败，而不是等到用户的 Koch 进度悄悄错乱。

断言消息用 ASCII 而不是中文：`tools/check_charset.py` 会把**字符串字面量**算进「界面
用到的字」，中文断言消息会白白占掉裁剪字库的位置，而它根本不会上屏（实测多算了
`冻布局改` 四个字）。

老设备升级上来 `battery_show` 取默认值 `CW_BATT_NUM`，界面行为不变。

### 9.3 真正的工作量在顶栏重排

电量只出现在主页顶栏一处（`ui_home.c`），右侧从右到左是百分比数字、电池图标、
WiFi 图标——而这三个位置原来是**写死的三个偏移**：`-6` / `-30` / `-56`。关掉电量
之后 WiFi 还钉在 `-56`，右边会空出 50px 一大块，看着像画坏了。

改成按实际显示的项依次推：

```c
int x = 6;
if (battery_show == CW_BATT_NUM)  { 数字 at -x; x += 24; }
if (battery_show != CW_BATT_HIDE) { 图标 at -x; x += 26; }
WiFi at -x;
```

三项全开时 `x` 正好回到原来的 56，**默认外观一像素都没变**。

`ui_home_set_battery()` 要对两个控件各自判空：battery 任务照常每 10 秒回调一次，
而「图标」模式下没有数字标签、「隐藏」模式下两个都没有。

改设置后要**回主页才看得到**——顶栏是在 `ui_home_create()` 里排的。这里不主动跳页：
用户在设置页连着调几项是常态，被踢回主页比晚看到一眼更烦。「屏幕旋转」能当场生效是
因为它走 `lv_disp_set_rotation()`，和这个不是一回事。
