起因是一个现场故障：两个人都切到 wire 10 却谁也听不到谁，而机器人 wire
（11 QSO / 12 回声）一切正常。查下去发现不是一个 bug，是四个，叠在一起。

## 修复

### 一、同呼号的对端被整个丢掉

`kob_client_rx()` 里有一条 `if (strcmp(p.id, c->office) == 0) return;`，注释写着
「服务器会把我自己发的包原样回给我」。用两个客户端同时挂到真实服务器
（`8.138.130.141:7890` wire 10）实测：**服务器只中继给别人，发送方自己一个
字节都收不到**。

```
--- A(BI8SYN) 发 'A'，B 的 office=BI8SYN ---
  A收到: []                                  ← 没有任何回显
  B收到: [(3, 'BI8SYN', 7, 4, "'A'")]        ← 中继正常
```

这条过滤从来没挡掉过任何回显，只挡掉了一种东西——对端呼号和我相同时，对方的
全部码包和 ID 包。

修法：判据换成 **id 相同 且 seq 落在我自己发过的号段里**，两个条件缺一不可。
号段起点在连接时随机取（`esp_random()`），所以同呼号的两台设备号段不重叠、
能正常互收；而真回显——万一哪天换了服务器实现真的开始回显——照样被丢掉。
实测服务器对 seq 只做透传、不做任何解释（发 `0x0A3B21C7` 起的号段，对端原样
收到）。

### 二、站点 ID 永远是出厂默认的 BI8SYN

配上第一条才致命：两台设备的 ID 都是 `BI8SYN`，于是互相把对方的每一个包当成
自己的回声丢掉。机器人 wire 不受影响，因为它们的 ID 是 `BOT` / `ECHO`，撞不上
——这就是「11、12 能通，10 不通」的全部原因。

`cw_net_cfg_t.office` 是 `set_defaults()` 里从呼号拷来的一份副本，而
`set_defaults()` 只在首次初始化（NVS 里还没有 blob）时跑一次——那一刻呼号还是
出厂值。之后用户改呼号，改的是 `cw_settings`，这份副本一动不动。

修法：删掉副本，新增 `cw_net_office()` 每次上线现取呼号。那 16 字节改作他用
（见「开机清理遗留出厂呼号」）。

### 三、换 wire 之后连不上，界面停在一个状态不动

`ui_nav_show()` 是先建新页、再 `lv_obj_del_async()` 删旧页——旧页的删除发生在
**下一拍**，那时新页早已建好、网络也起来了。而对练页的 `LV_EVENT_DELETE` 回调
无条件执行 `kob_net_stop()` + `lv_timer_del(s_timer)` + `s_scr = NULL`，于是从
对练页导航回对练页时，旧页这次迟到的删除把**新页刚起的网络和刚建的定时器**
一起关掉了：`poll()` 从此直接返回，界面冻在最后画上去的那一帧。

这条是既有缺陷。v1.4.2 加 wire 选择器之后（`apply_wire()` 走的正是
`ui_nav_show(ui_net_create)`），**每一次换 wire 都会踩到**——「两个人都切到
wire 10」多半也有它一份。

修法两处：删除回调只在 `lv_event_get_target(e) == s_scr` 时才收摊；换 wire 改成
就地重连（下一条），不再重建页面。

### 四、换 wire 会把 WiFi 驱动拆了又装

整页重建会走 `kob_net_stop()` -> `wifi_net_stop()` -> `esp_wifi_deinit()`，几十 KB
的 WiFi 驱动在 LVGL 事件回调里卸载再初始化，全程堵着 UI 线程；而
`wifi_net_stop()` 并不等 `wifi_net` 那个连接 worker 退出，deinit 会从它脚下把
驱动抽走。

修法：新增 `kob_net_rewire()`——只停 socket 任务、按新 wire 重开一遍，**射频
一根手指都不碰**。换一条线路不该牵动到射频。

## 改动

### 出厂呼号留空，没有呼号不上线

呼号会作为站点 ID 上到 wire 上，一条 wire 上两个同名站点分不清谁是谁。而没人
会去改一个「看起来已经填好了」的设置——出厂值 `BI8SYN` 正是这样让所有设备撞成
同一个 ID 的。

留空则是个明确的「还没填」：对练页在没有呼号时不联网，收报区（本来就空的那块）
显示一个「设置呼号」按钮，点了进呼号页，填完回来就正常联网。本地练习不受影响
（呼号为空时回退成 `NOCALL`）。

**中途走过一段弯路，记下来**：这里先做成了自动弹出的弹窗，结果弹窗在
`ui_net_create()` 里创建，而那是 `ui_nav_show()` 的 builder——`builder()` ->
`lv_scr_load()` -> `del_async(old)` 的顺序意味着此刻 `lv_scr_act()` 还是正要被
删掉的上一屏。弹窗挂上去就随它一起消失（表现为「进对练页什么都没弹、也不
联网」），留下的野指针下一次去删就把堆搞坏，LVGL 在
`lv_obj_set_style_bg_color` 里空转到任务看门狗复位。按钮没有这个问题。

### 开机清理遗留的出厂呼号

上一条只对新设备必然生效——已经在用的设备存着老出厂值 `BI8SYN`，呼号非空，
拦不住。所以升级后开机检查一次，是 `BI8SYN` 就清空。

**只清一次**：`BI8SYN` 是个合法呼号，真有人叫这个，每次开机都清的话那个人永远
设不上自己的呼号。判据是 `cw_net_cfg_t` 里原来 `office` 那 16 字节，现在改放
「用户亲自在呼号页按过确定」的标记。复用而不是新加字段：加字段会改变结构体
长度，就要提版本号写迁移，而每改一次这个 blob 都是一次冲掉用户 WiFi 密码的
机会（v1->v2 那次就冲了）。老设备这里存的正是旧的 `office` 值，不等于标记，
正好被当成「还没定过」，升级路径不用额外处理。

### 站点表：能加也能减，且发现是即时的

原来 ID 包只在建立连接时发一次，于是站点表两头都是错的：晚加入的人永远看不到
早到的人（对方的 ID 早发完了），已经离开的人永远留在表里（`on_peer()` 只增
不减）。

三条一起做：

- **ID 信标**，每 10 秒一次。用自己的时间戳，不蹭 `last_tx_ms`——正在连续发报的
  站点 `last_tx_ms` 一直在刷新，蹭它的话信标永远发不出去，而那恰恰是最需要让
  别人知道你在的时候。
- **收到别人的 ID 立刻回报自己的**，限速 2 秒。只有信标的话，发现延迟等于
  「等对方下一拍」——平均 5 秒、最坏 10 秒，一进线路顶栏要愣半天。现在一个来回
  （实测 30ms）就互相看见了。限速保证收敛：A 报身份 -> B 应答 -> A 收到应答但
  刚发过、落在窗口内，不再应答，到此为止。
- **35 秒没出现就摘掉**（约 3.5 个信标周期）。协议里没有「某人退出了」的通知,
  DIS 是发给服务器的、服务器不转发，只能靠超时推断。码包也算「还活着」——只认
  ID 包会把正在连续发报的站点判成失联。

加是秒变、减要等 35 秒，这个不对称是协议决定的，不是实现问题。

**这里自己踩了一个坑，值得记**：`on_peer()` 自己读钟，`peer_sweep()` 却用了
主循环顶部的 `t`，两者之间隔着一个最多阻塞 20ms 的 `recv()`。拿 `t` 去减一个
更晚的时间戳，无符号下溢成 42 亿，远大于 35000，站点刚加进来就被摘掉——人数
在 0 和 1 之间反复闪。现在 `peer_sweep()` 自己读钟，两处读同一个单调时钟，
且扫描必然发生在后面。

### 顶栏

从右往左是 **`[wire 方框]` `N 人`**。

- wire 挪到最右，加描边方框，去掉原来的 `>`。方框本身就是「这是个按钮」，不
  依赖任何字形；`>` 是从列表行的「更多练习 >」借来的约定，但列表整行可点、
  箭头只是方向暗示，搬到顶栏太轻了，看不出可点。wire 是本页唯一可操作的东西，
  放最边上手指最好够到。
- 右侧只报人数（不含自己），不再显示呼号。一条 wire 是共线，人数才是这里唯一
  稳定有用的信息；呼号最多塞得下一个，那个「第一个」纯粹取决于谁的 ID 先到，
  没有意义，而谁在发报，收报记录每一行前面本来就写着。
- 同呼号时显示 `N 人 呼号重复`——警告保留，但不再重复那个呼号。用词受裁剪
  字库限制：`同`/`改`/`相`都不在表里，`tools/check_charset.py` 会拦下来。

### 去掉两条提示

- **「XXX 正在发报 - 按电键将打断」**。本意是提醒误触的代价，实际效果相反：
  对方一开始发，状态带就被这句话占满，而那恰好是你最想跟着打一遍、最需要看清
  自己点划的时候。谁在发报顶栏和收报记录都写着，打断与否是电键本来就有的语义。
  在线时状态带现在只做一件事：显示本机正在打的点划。
- **侧音底噪提示**。它占着收报记录的第一行，而绝大多数人第一次进来看到的就是
  它——想练的东西被一句注意事项挡在前面。`noise_notice_shown` 字段标废弃、
  保留字节。

### WiFi 常连，不再按需开关

spec 3.5 原来定的是「WiFi 默认关闭、按需开启」，三条理由里最重的一条是**侧音
底噪**：侧音走 ESP32 内置 DAC，WiFi 发射的电流尖峰可能在耳机里听成周期性底噪，
而离线练习是主线场景。spec 473 行把它列为必测项、标注「主观听感，但必须测」
——一直没测过，却撑着整个设计。

2026-08-28 实测：**联网对练全程听不出可闻底噪**。而联网对练正是发射最密集的
场景（每字符一个包 + 保活），常连待机只会更轻。于是改为开机就连、一直保持，
进对练页不再干等几秒握手。

剩下两条代价是实测过的：常驻内存 **57KB**（free heap 164008 -> 105752，与 spec
估的 50~60KB 吻合），TX 峰值 250~300mA。

**「保持连接」不是「连上一次」**，这里补了三件事，缺一个都不成立：

- **掉线自动重连**。ESP-IDF 不会自己重连，AP 重启、走出覆盖范围都会断链。
- **退避重试**，5 秒起、逐次加倍、封顶 60 秒。实测设备第一次握手就失败了
  （`auth/assoc failed for Corona_5G`），旧代码到此为止、永远没网；现在退避
  之后连上。
- **逐个试备用网络**。原来只试信号最强的那一个。「最强的密码是错的、旁边还有
  一个能连」很常见（路由改了密码、隔壁同名 AP）。

顺带修了个潜在崩溃：`wifi_net_stop()` 原来不等 worker 退出就 `esp_wifi_deinit()`,
等于从一个还在调 `esp_wifi_*` 的任务脚下抽走驱动。worker 现在是常驻的，这个必
须先停再拆——不过射频既然不再关闭，`wifi_net_stop()` 本身也随之删掉了。

`wifi_net_prefer()` 也必须跟着改：它原来只改一个变量，靠「下一次连接」生效，
而以前每次进对练页都会重连一遍，那个「下一次」总会来。现在连接一直在，不主动
断开的话，用户在设置里换「连接网络」会毫无反应。

### 网络对时，主页时钟不再是 --:--

主页左上角的时钟一直显示 `--:--`，因为系统时间从没被设置过。加 SNTP
（`ntp.aliyun.com`，时区固定 `CST-8`）。

第一版是开机就让 SNTP 跑起来，**第一次对上花了 81 秒**：请求在 968ms 发出，
那时 WiFi 还在握手（4974ms 才拿到 IP），打空之后就是 lwip 的指数退避在等。改成
监听 `IP_EVENT_STA_GOT_IP` 再启动，**第一发就中，1.9 秒**。每次拿到 IP 都催一次
`esp_sntp_restart()`——设备可能在没网的地方躺很久，而 SNTP 自己的下一个更新周期
是一小时。

时间不跨断电保留：RTC 只在软复位/深睡时续着走。不往 NVS 存时间，那点便利换不来
额外的闪存擦写，而 NVS 分区还和 fmo-companion 共享着。

### 主页顶栏正中显示呼号

没设置就整个不建这个标签——留一行占位或者写「未设置」，等于把一个空状态天天挂在
主界面上，而真正需要呼号的地方（联网对练）自己会拦、会提示。

### 开机提示音：一个 V（...-）

`V` 在 CW 里就是**试机信号**，历史上调谐、试设备发的就是 `VVV`，含义正是「设备
开着、工作正常」。没有用 `CQ`：那是「呼叫任意电台寻求通联」，开机时并没有在呼叫
谁——这台机器是训练器，它发出的每个声音都是教材，不能拿语义不对的信号天天教人
（`73` 是告别、`AR`/`SK` 是结束，放在开机更反）。

速度固定 20 WPM，不跟用户的 `char_wpm` 走：设成 5 WPM 的人开机要干等好几秒，而
这一下本来就该是「一响」不是「一段」。播完在 `DONE` 回调里把节奏还原成用户的
设置，否则之后所有听写和收报回放都会跟着变成 20 WPM。音量走现有的音量设置，
不另加开关。

## 升级须知

升级后第一次进「联网对练」会要求设一次呼号，这是有意的——两个人对练，各自的
呼号必须不同，否则屏幕上分不清谁是谁。

## 验证

- 主机测试 105 个全过；`tools/check_charset.py` 全部命中
- 设备实测：wire 10 双向通联（对端逐字符收到）、换 wire 不断线不卡死、人数
  即时增加、站点退出后约 35 秒减少、开机清理遗留 `BI8SYN`（NVS 读取确认）、
  WiFi 开机自连与断线重连、SNTP 对时 1.9 秒、开机提示音
