## 新增

### 外接电键接 CN3 的 IO18 / IO23

外接电键的代码其实一直都在（去抖、Iambic A/B 都实现了），卡住的是引脚。原来的
`BOARD_KEY_DAH_GPIO` 是 GPIO27，空闲电平恒为低，一启用外接口就是「划桨一直按着」，
与操作者是否碰过键无关。

`board_config.h` 里为此写了 33 行注释，推测原因是板子把这条网络设计成扩展 SPI 的
片选输出、上面有比内部弱上拉更强的外部偏置。**这个推测是错的**：真实原因是本机
改装时 GPIO27 上接了蜂鸣器（已记进 `docs/hardware.md`「本机改装」）。

换到 CN3 的 IO18 / IO23。判据是**方向**：板子把这两根规划成 SD 的 SCK/MOSI，也就是
ESP32 往外送的输出，卡座那侧只是接收端，板上没有任何器件会跟输入抢电平——正是
GPIO27 踩过的坑的反面。相比之下 IO19 是 SD 的回读线（插了 TF 卡时卡片的 DO 会驱动
它），IO35 属于 34~39 输入专用段没有内部上下拉，IO22 是板载 RGB 绿灯通道。

| | 面包板按键 | 3.5mm TRS 成品电键 |
|---|---|---|
| 点 | CN3 脚2 = IO18 | **Tip** → IO18 |
| 划 | CN3 脚4 = IO23 | **Ring** → IO23 |
| 地 | CN4 脚1 = GND | **Sleeve** → GND |

Tip=点 / Ring=划 / Sleeve=地 是 Elecraft / Yaesu / Icom / Kenwood / Begali 一致的
行业约定，两种接法在固件里完全不可区分。低电平有效、内部上拉，不需要任何外接元件。
接线细节见 `firmware/cw-trainer/README.md`「外接电键」。

### 触摸桨与外接口并联，「电键输入」设置项删除

两路按位或，谁按都算，不用再进菜单切换。按外接电键时**屏幕上对应的那一块跟着变灰**。

`cw_settings_t.key_input` 字段随设置升到 version 3 一并删除，见下方「设置升到
version 3」。

### 一根线恒为低时不再把电键钉死

外接口从「选中才采样」变成永远采样，于是一根空闲即为低的线会把电键彻底钉死——而且
合并是或运算，同侧的触摸块会跟着一起失效。

规则：**一根线必须先被观察到「松开」过一次，才被允许说话。** 判据用去抖后的值而不是
原始电平——原始电平上一个方向相反的毛刺就足以给一根真正卡住的线开闸，而开闸之后
去抖值仍然是「按下」，键照样被钉死。

这不只是为 GPIO27 那次意外准备的：成品**直键**配的多是 TS 单声道插头，插进 3.5mm
立体声母座时套筒会把 Ring 和 Sleeve 短接、划线恒为低，**每插一次直键都会发生**。
配合「电键类型 = 直键」就能直接用。

被挡住时电键页的点划行会直说是哪一根（`外接划线(IO23)一直按下`），提示留到你第一次
碰键为止。静默忽略一根坏线的表现是「按了没反应且毫无线索」，那正是 GPIO27 那次最难
查的地方。

### 电量显示可以关掉

设置 → 常规 → **电量显示**：`隐藏 / 图标 / 图标+数字`，出厂默认「图标+数字」。
**有人根本没接电池**——那个电池图标和百分比对他们只是噪音，而且读数还是假的
（没有电池时 ADC 量到的是分压网络上的残留电平）。

做成一项三选一而不是两个开关：两个独立开关会造出「百分比开着但电量关了」这种无效
组合，要么置灰、要么允许一个没有效果的开关存在，都不如一项干净。

真正的工作量在顶栏重排。电量只出现在主页顶栏一处，而右侧三个位置原来是写死的偏移
（`-6` / `-30` / `-56`）——关掉电量之后 WiFi 图标还钉在 `-56`，右边会空出 50px 一大块。
改成按实际显示的项依次推出位置；三项全开时算出来正好是原来的数值，**默认外观一像素
都没变**。

改完要**回主页才看得到**：顶栏是在 `ui_home_create()` 里排的。这里不主动跳页——在设置
页连着调几项是常态，被踢回主页比晚看到一眼更烦。

### 「电键类型」加了一句说明

选 Iambic A 或 B 时，值下方显示「A/B 之别需双桨同按，仅外接电键可分」。电阻屏不支持
多点触控，用触摸桨时选 A 还是 B 行为完全一样——不说的话，用户会以为自己选的没生效。

## 修复

### 直键模式下对练页和手法页的右半块是死的

电键页自己写了三条布局分支，而对练页和手法页无条件铺两块桨。直键模式下
`keyer_tick()` 只看 `dit_in`，右边那块根本不接线，按了没有任何反应。

布局收进 `ui_keyer_paddles()` 一处，三个铺电键的页面（电键 / 对练 / 手法）从此长得
一模一样，一次修三页。

### 开了「桨键左右对调」后屏幕标签在撒谎

左块永远印着「点」，但对调之后它发出的是划。现在标签跟着换：开对调后左块印「划」、
右块印「点」。

顺带定下**直键不参与对调**：单个触点没有「左右」可言，而真按对调处理的话，屏幕上那
一整条会被换到划线上，`keyer_tick()` 的直键分支只看点线——结果是开了对调之后屏幕
直键按了完全没反应。外接直键同理固定留在点线（IO18 / TRS 的 Tip），这也正是 TS
单声道插头的接法。

### 设置升到 version 3

加 `battery_show` 必须升版本。顺便把 v1.5.0 前半程留下的 `reserved_key_input` 死字节
真正删掉——当时保留它是为了避开升版本，理由是「v3 和 v2 的 sizeof 相同会让迁移分支
分辨不出彼此」，**那个判断是错的**：`cw_settings_init()` 里 v1 分支判的是
`len == sizeof(v1) && version == 1`，版本字段本来就在消歧，同长度从来不是问题。

v3 删掉 `key_input`、末尾加 `battery_show`，一减一加抵消，结构体仍然是 68 字节。
v1/v2/v3 三者长度全相同，所以必须靠 version 字段分辨。两个历史布局快照加了
`_Static_assert(sizeof(...) == 68)`：它们描述的是已经写在别人设备 NVS 里的字节，
谁「顺手整理」一下就会把老配置读错位。

**老设备升级上来 Koch 进度不丢**，`battery_show` 取默认值，界面行为不变。

### OTA 会把设备静默降级，且 v1.10 之后所有设备都升不了级

`ota.c` 原来判「有没有新版本」用的是 `strcmp(服务器版本, 本机版本) != 0`——**不等
即有更新**。于是本机跑着比服务器新的版本时（发布前的本地构建就是这样）会一直提示
「有新版本」，而那个提示点下去是**静默降级**，用户以为自己在升级。

更隐蔽的是 `strcmp` 的排序本身就是错的：`strcmp("v1.10.0", "v1.9.0") < 0`，因为
`'1' < '9'`。这个工程迟早会到 v1.10，到那天所有设备都会拒绝升级且没有任何报错。
**即使不修提示，字符串比较也必须换掉。**

改成 `core/version_cmp.c` 的语义比较（纯函数，8 条主机侧单测），并把「更新」和
「不同」拆成两个标志：

- `available`（更新）→ 主页提示条、设置页「有 vX」，**只有它会主动打扰用户**
- `differs`（不同，可能更旧）→ 升级页仍允许手动安装

**降级通道保留**：出问题时在服务器上挂回旧版把设备拉回去是真实有用的救急手段。
只是界面上要说实话——按钮写「装旧版」而不是「升级」，设置页写「服务器 v1.4.4」而不是
「已最新」。

版本号解析不了时**不猜**，`available` 保持 false 并打警告日志：把看不懂的版本号猜成
「更新」，代价是把用户降级到一个不知道是什么的固件。

> 需求最初的设想是「json 里加构建号，每次构建递增」。没采纳——毛病在**比较运算符**
> （`!=` 而不是 `>`），不在标识的粒度；加了构建号仍用 `!=` 症状一模一样。而构建号会
> 成为第二个权威（`release-process.md` 定死 `PROJECT_VER` 是唯一权威），且没有好的
> 存放处。理由详见设计记录 §2。

### 电键块跨页面 static 的 use-after-free 隐患

`ui_keyer.c` 里 `s_pad[]` 是文件级 static，而 `ui_nav_show()` 会先建好新页面再异步
删除旧页面。原来靠「每条布局分支各自负责清零自己不写的下标」来绕，光是解释就花了
10 行注释。高亮状态改成每组桨一份、动态分配、挂在 pad[0] 的删除事件上自毁，
`s_pad[]` 不再需要存在，结构上没有这个洞了。

## 改动

- 联网对练里 wire 11 的显示名从「QSO 陪练」改成「**AI 陪练**」——这条 wire 上的陪练
  已经由语言模型驱动，不再是脚本状态机。宏名 `CW_NET_QSO_WIRE` 不动，它指的是服务端
  `cwbot-qso` 这个服务占的那条 wire，服务名没变。
- 电键块的高亮**只在状态变化时写** `bg_color`：`lv_obj_set_style_bg_color()` 会触发
  样式刷新并让对象失效重绘，每 50ms 无脑重写会让电键块持续闪烁。

## 验证

- 主机测试 **13 个程序、127 个用例**全过。新增 `test_key_merge.c` 10 条覆盖
  「并联 × 门闩 × 左右对调」的交互——合并逻辑抽成了 `core/key_merge.c` 的纯函数，
  在此之前它和 GPIO 读取、FreeRTOS 任务缠在一起，一条测试都写不了。
- `tools/check_charset.py` 拦下 15 个表外的字，已重新裁剪 `fonts/font20_cwtrn.c`。
  用到表外的字不会编译报错，只会在屏幕上渲染成空白。
- **`check_charset.py` 自己也修了一个假阳性**：诊断字符串（`ESP_LOG*` 和
  `_Static_assert` 的消息）是字符串字面量，会被算进「界面用到的字」，而它们永远不会
  上屏。这不是小事——字库大小直接决定 OTA 能不能用（`ota.h`：裁剪前固件 2.2MB，双槽
  放不下）。加了 `strip_diagnostics()` 之后界面字符数 389 → 370，裁剪字库
  60.6KB → 55.5KB。被排除的 19 个字逐个回查过，确认没有一个出现在非诊断的字面量里
  ——假阴性会让屏幕出现空白，比多几个字形严重得多。
- 设备实测：不碰键时完全安静；IO18 出点、IO23 出划、左右块分别变灰；两键同按点划
  交替；触屏与外接同时可用；长按 10 秒高亮不闪；直键模式下三个页面都是一整条；
  对调后标签互换；对练页显示「AI 陪练」。
- 设置结构体三个版本的 `sizeof` 实测均为 68，版本字段消歧成立。
- `test_version_cmp.c` 8 条，其中一条专门钉住 `v1.10.0 > v1.9.0`——那是换掉 `strcmp`
  的首要理由，不是补充。
