铜色为什么是 #945418 而不是更漂亮的 #A8641E

本来选的暖铜 #A8641E 在纸底上实测只有 3.67:1，达不到正文 4.5:1 的下限，只能做填充不能做文字——那就得拆成「填充铜」和「文字铜」两个值，等于两个 accent。往下压到 #945418 拿到 4.78:1，一个值同时能做文字和填充，色板回到一个 accent。少一个 token 比多一点艳度值钱。

铜色的用量上限

整屏铜色不超过两处，且必须编码同一件事：「现在轮到这里 / 这是主操作」。具体只允许出现在——主操作文字或按钮（如「继续练习 >」）、进度条填充、当前选中项、电键按下时的桨块。

  • 不用铜色做标题、图标、分割线、装饰。
  • 不用铜色表示「答对」——那是状态语义，答对答错用 ink / danger。
  • 去色测试：把整屏想成黑白的，层级仍然清楚（靠字号 + 留白 + 规则线撑），铜色拿掉只丢失「主操作在哪」这一条信息。这是合格的。
Type

字体层级

这是目前最大的瓶颈：中文只有一级字号。font28 和 EN_BIG 都不含中文字形，代码里到处是「含中文必须留在 UI_FONT_CN」的注释——中文文案之间做不出大小对比，只能靠位置区分主次。

级别字体行高字符集用途
DisplayEN_BIG82ASCII结算百分比、电键 WPM 大字
Titlefont28 + 新增中文37ASCII → 补 CJK页面标题、卡片主标题
Bodyfont20 / font20_cwtrn26350 字形正文、列表项、按钮
Captionlv_font_montserrat_1417ASCII顶栏状态、标签、单位

全工程四级，单屏不超过三级（工艺规则上限）。新增的中文字号定在 28px 而不是另挑一个 36/40——它要和已有的 font28 并排落在同一基线上，中英同级才不会在一行里高低不齐。

关键发现：仓库里没有源 TTF

tools/subset_font.py 的文件头写明了：font20.c 是第三方「Lvgl Font Tool V0.4」生成的 XBF 格式，那个脚本做的是 C→C 裁剪，正是因为没有源字体。所以补 28px 中文不是再跑一次裁剪，而是必须引入一套新 TTF，用 lv_font_conv 重新生成。

字体方案

既然无论如何要换，就用同一套 TTF 同时重出 20px 和 28px，让中文正文和标题是同一款字——而不是留下「20px 是旧字体、28px 是新字体」的错配。候选按复古方向排：

  • 标题宋体 + 正文黑体（推荐）。28px 撑得住宋体的横细竖粗，最贴电报房调性；20px 正文留黑体保证小字可读。bpp=4 有 16 级抗锯齿，宋体在 28px 上不会糊。
  • 全黑体。最稳，复古感全交给配色和纹样承担。宋体在电阻屏上不好使时的退路。

下面主页样稿出了两版供对比。最终选哪个要在 SDL 模拟器里用真 LVGL 渲染看过再定——浏览器的字体渲染和 LVGL 的 4bpp 位图不是一回事，这里的样稿只能定方向，不能当验收。

闪存账：固件 1.34 MB，OTA 单槽 1.6875 MB，余量 362 KB。新增 28px 中文子集（350 字形，4bpp）约 +106 KB，20px 换字体基本等量替换。改完余量约 256 KB。付得起。

改动中文文案后仍须走原有流程：python3 tools/check_charset.py 自检 → 重新生成子集。漏字不会报编译错，只会在屏幕上渲染成空白。

形状与效果的硬规则

  • 圆角一律 0。 纸和铅字没有圆角，且省掉 LVGL 圆角抗锯齿开销。现有代码到处 radius=0，这条等于免费。
  • 线宽一律 1px。 主结构线用 ink，组内次级线用 rule。延续现有单边线（BORDER_SIDE）策略，不画整圈描边。
  • 不做大面积渐变——实时的和烘焙的都不做。 实测（样机第 2 页）连离线抖动过的都有可见台阶。色块一律平涂。
  • 暗部走 1px 浮雕，不走 shadow_*。 实测 1px 高光/暗线在雾面膜下清晰可见，且零成本。实时阴影不贵（w8 每对象约 1.3 ms）但表达力不够，只在需要分层时偶尔用。
  • 纸纹分两档。 装饰区（卡片底、页面底）σ=7，密集文字区 σ=4——实测 σ=7 压中文会略微变难读。
  • 不加动效，保留瞬时反馈。 现有 no_fade_transition 把主题的按下/松开渐变顶成 0ms，这条继续保留——电阻屏本身就有输入延迟，再叠渐变只会更钝。反馈靠按下瞬间换 sunk 底色，符合「每个操作都有反馈」。
  • 唯一允许的装饰：点划纹样。 用 ink3 画当前课字母的莫尔斯序列作分隔纹样。它编码真实信息（本课学什么），不是纯装饰。
Skeuomorphism

拟物层：分层拟物

拟物在这块硬件上成不成立，取决于「暗部」怎么画。这三件事在 LVGL 里名字都叫阴影，成本差两个数量级：

做法运行时成本闪存质量
① LVGL shadow_* 实时投影贵，每次重绘重算蒙版0只有柔和外阴影一种
② 1px 高光线 + 1px 暗线浮雕≈ 0（就是两条线）0硬边浮雕，实体面板感
③ 烘焙进贴图（渐变/阴影/纹理）≈ 0（闪存 memcpy）按面积算最好，抖动离线做，完全可控

原本的判断是「①有色带，③把抖动挪到离线做就能救」。样机第 2 页推翻了后半句：离线 Floyd–Steinberg 抖动过的那一行，台阶照样看得见。这块屏在这个亮度范围上就是表现不了连续色调。

风格因此收紧：拟物 = 压印，不是光泽

既然大面积渐变怎么做都不平，就不做渐变。拟物的三件套改成 平涂 + 浮雕 + 纹理：色块一律平涂，立体感全靠 1px 高光/暗线（实测可见、零成本），质感靠纸纹噪点（实测这块屏能吃 σ=7）。

这不是退让，是更对的答案：电报房本来就该是压印质感（letterpress），不是 iOS 6 的玻璃光泽。纸、铅字、黄铜刻痕——这些东西的立体感本来就来自边缘的明暗，不来自表面的高光渐变。硬件的限制和风格的方向这次是同一个方向。

烘焙贴图仍然有用，但用途从「救渐变」变成「给材质」——木纹、黄铜拉丝、纸纤维。而材质本来就是噪点，不需要平滑，正好绕开了这块屏最不擅长的事。

策略：钱只花在一个地方

不做全套 iOS 6（皮革缝线、玻璃反光、处处柔和投影）——那套在 320×240 的雾面电阻屏上会同时输掉可读性和精致度。改成两层：

  • 打底：浮雕，零成本。 卡片、按钮、输入格一律用 1px 高光/暗线做压印与凸起。和纸底铜色天然兼容——纸被压出凹凸，比贴一层假皮革更贴电报房的调性。
  • 重点：电键页做真拟物。 这是唯一一个屏幕元素直接对应用户手上真实物件（电键桨）的页面，拟物在这里承载真实语义而非装饰。黄铜、木质底座、按下时真的下陷。整机的分量由这一页负责。
  • 不做：柔和大投影、玻璃高光、全屏纹理堆叠。

一句话：其他页面是「纸」，电键页是「桌上的那把电键」。

位图格式：两个能省大钱的选择

格式每像素适用示例开销
LV_IMG_CF_INDEXED_4BIT4 bit16 色调色板。纸底+铜色的有限色板正好吃这个全屏 320×240 = 37.5 KB
LV_IMG_CF_ALPHA_4BIT4 bit单色 + 16 级 alpha。烘焙阴影的最佳容器——阴影本质就是 alpha 蒙版64×64 阴影 = 2 KB
LV_IMG_CF_TRUE_COLOR16 bit需要连续色调时（渐变、木纹）全屏 = 150 KB

平铺用 lv_obj_set_style_bg_img_src() + bg_img_tiled(true)——v8 里唯一的平铺方式，一张 32×32 的小图（2 KB）能铺满任意面积。按下态用 img_recolor 而不是存第二张图，素材量直接减半。

必踩的坑：CONFIG_LV_COLOR_16_SWAP=y

查 lv_color.h，16 位带 swap 的位域顺序是 green_h(3) / red(5) / blue(5) / green_l(3)，小端填充下 full == byteswap(标准 RGB565)。所以位图数据里每个像素必须按大端（高字节在前）写。写反了不报错，只会看到红蓝错乱的一片。

电键页拟物预算（估）

两个桨各约 140×88，INDEXED_4BIT 各 6.2 KB；按下态走 img_recolor 不另存图；木纹底座用 32×32 平铺瓦片 2 KB。合计 15–25 KB。扣掉字体的 106 KB 后余量 256 KB，付得起。

Probe

素材样机与实测结果

拟物必须在真机上判。SDL 模拟器在这一条上没有裁决权：它跑在 32 位色的好显示器上，既没有 RGB565 的色阶损失，也没有电阻触摸那层雾面膜，更没有这块 ST7789 的 gamma 和可视角。所以在投入做素材之前，先烧一页样机把问题问清楚。

入口：更多练习 → STYLE PROBE，顶栏右上 NEXT > 翻页，共六页。2026-09-01 已在真机上跑完，结论见下。

配置整屏耗时相对无阴影折合单对象
无阴影48 277 µs——
w8 × 3 个对象52 168 µs+3 891 µs（+8%）≈ 1.3 ms

半径翻倍、单对象成本涨 3.7 倍，符合模糊的平方级增长。但真正该注意的是那 48 ms 的底噪：整屏重绘 ≈ 21 fps 上限，这是现在就存在的页面切换代价，与拟物无关（SPI 理论最快也要 15.4 ms，其余 33 ms 是 CPU 渲染）。

修正：之前写的「实时阴影彻底封杀」不成立

样机测的是整屏重绘，而实际使用中 LVGL 只重绘失效区域——按一下按钮只重画那个按钮。所以真实问题是「64×64 的局部重绘多花 1.3 ms 要不要紧」，答案是不要紧。

封杀的理由因此从「太贵」换成「表达力不够」：LVGL 的 shadow_* 只有柔和外投影一种，做不出浮雕、内阴影、材质，而那才是拟物需要的东西。小半径外投影作为分层手段可以保留，需要时就用。

构建方式

ESP_PORT=/dev/cu.usbserial-XXXX PROJECT=firmware/cw-trainer tools/idf.sh -DCW_STYLE_PROBE=ON build flash

样机默认不编入：CW_STYLE_PROBE 关闭时固件 1 406 992 字节，与加样机之前一个字节不差；打开后 1 464 320 字节（+56 KB，其中烘焙位图 49.6 KB）。注意这个 option 会留在 CMake 缓存里——回发布版必须显式写 -DCW_STYLE_PROBE=OFF，不能只是省掉参数。

位图由 tools/gen_probe_assets.py 生成（Floyd–Steinberg 抖动 + 大端 RGB565），改完重跑即可。

统计暴露的两件事

accent 只有一个落点——整个固件目前只有主页的「继续练习 >」在视觉上被标记为主操作。换成铜色时不会满屏开花，和「整屏铜色不超过两处」的规则天然吻合。

两处只有看真机导图才发现的问题

统计页一屏八根铜色柱子。直接违反本文自己定的「整屏铜色不超过两处」。数据是墨不是 accent——铜色要留给「现在轮到这里」。于是拆出 UI_DATA（#6B5D4A，5.19:1），UI_FILL 的铜色只留给 OTA 进度条那一处真正的「正在进行」。

浮雕暗线定浅了。原定 #B5A88C 对纸底只有 1.88:1，而抬高面和纸底本来就只差 1.11:1——「更多练习」那种整宽格子于是糊成一整片。改成 #9C8C6E（2.63:1）：像素实测边界是「一条暗线 + 一条亮线」的 2px 凹槽，正是压印该有的样子；再深就要开始和正文抢注意力。

这两条都是指纹查不出来的——指纹只回答「变了没有」，回答不了「变得对不对」。所以给巡检加了导图模式（-DCW_SCREENSHOT_DUMP=ON），把像素 base64 出串口，tools/screendump_to_png.py 拼回 PNG。慢（每页约 18 秒），但这是唯一能看见真机长相的路。

第二轮真机反馈修掉的四处

1. 电键上的横向台阶。看着像渐变，但工程里根本没有渐变——是黄铜的「拉丝纹」。原来每行取一个随机亮度偏移（sigma=6）模拟金属方向性，而黄铜 #A8763C 附近 8 位色差 2 个单位在 RGB565 里红通道就跳一整级；「同一行内高度相关」恰恰让这一档铺满整行，32px 瓦片一平铺，横条就规律重复。改成各向同性细颗粒后，实测黄铜区 61 行里没有一行是单色（每行 10–27 种颜色），行相干性结构性消失。
规律：16 位色上任何行/列相干的低幅变化都会被量化放大成条带。纸纹一直没问题，正因为它本来就是各向同性的。

2. 三处没有浮雕。首页「继续练习 >」、顶栏返回箭头、对练页呼号 badge——共同原因是它们根本不是按钮，全是加了背景色的 lv_label_create，ui_bevel() 从没走到它们身上。而这三个里有两个是全屏最重要的操作。新增 ui_bevel_edge()：只画背光那两条边、不新增子对象，专给 LV_SIZE_CONTENT 自适应的对象用（ui_bevel() 的子对象靠 LV_PCT(100) 贴合，碰上自适应尺寸就对不准）。

3. 选中态太弱。UI_SELECTED 原来直接复用凹陷面 #E4D9C3，对抬高面只有 1.24:1，真机上看不出选了哪个 tab。改 #C8B996（1.71:1）。凹陷面是给「压进纸里的一条」用的，选中态需要更明确的一档。

4. 对练页状态带该下沉。它下面紧接着就是抬起来的电键桨，一凹一凸层次才立得住。改 ui_bevel(bandbg, false)，像素实测上沿 #9C8D6A 暗线 → 面 #E6DAC5 → 下沿 #FFFAF6 亮线，标准凹槽。

第三轮真机反馈：一个真 bug，一个更隐蔽的真 bug

1. ui_bevel() 遇到有 padding 的对象就画错。子对象用 LV_PCT(100)，而 LVGL 的百分比相对的是内容区：父对象有 pad 时内容区缩进去，浮雕线就画在距边缘 pad 那么远的地方。首页那张 pad_all(8) 的大卡片正是如此，按下变色时那个内缩 8px 的框一下就暴露了。改成按调用时的实际 pad 反推 transform，并要求必须在设好 padding 之后调用。

2. 黄铜的颜色根本不来自 UI_BRASS。桨上铺的是不透明的平铺贴图，它把 bg_color 完全盖住——改宏对观感毫无影响（改了之后电键页指纹一个字节没变，这才发现）。真正的颜色写死在 tools/gen_ui_assets.py 里。
连带后果更严重：电键桨按下时没有任何颜色变化，因为按下态改的也是 bg_color。改走 bg_img_recolor（opa 190——拉满 255 会变成一块死平的深色，材质白做了）。

3. 按钮按下没有下沉。当初写死「按下不翻转浮雕」，理由是 LVGL 状态不向子对象传播——那个理由站不住，挂个事件回调就行。现在按下时浮雕真的翻成凹陷，像素实测：上左 #FFFAF6→#83795A、右下 #9C8D6A→#DED6D5。必须同时接 LV_EVENT_PRESS_LOST，否则手指划出对象外会永远卡在按下的样子。

4. 三处语言不统一。首页「开始练习 >」撤掉了按钮外观——整张卡片本身就是那个按钮，在它内部再画一个键等于把可点区域说小了。对练页的 wire 选择器改成和电键页「清屏」同一副长相（抬高面 + 浮雕），全工程的可点元素只讲一种话。呼号牌从「黑底白字」改成压进纸里的一枚戳（凹陷面 + 墨字 11.64:1）——黑底白字是上一版高对比主题的写法，搬到纸面上就是一块块黑疤，而日志区每行都有一个。

导图也补了「按下态」：对页面里第一个 lv_btn 发一次按下事件再导一张。注意不能按 LV_OBJ_FLAG_CLICKABLE 找——LVGL 8 里 lv_obj_create 默认就带这个标志，第一版因此选中了顶栏那个纯容器，导出来的「按下态」和常态一模一样。

第四轮：顶栏的两个键贴着边、且没有按下反馈

根因是顶栏高度一直没按计划改。上面 8px 网格那张表里「28 → 32」写了很久，但只写在纸上——而 UI_FONT_CN 的行高就是 26，28px 的栏里但凡放个带内边距的控件就装不下：返回键写死 36 × UI_TOPBAR_H 正好占满上下贴边，对练页的 wire 选择器加了 pad_ver 2 后是 30，比栏还高，直接被挤出去。

落地 32px 之后，新增共享控件 ui_chip()：高度就等于行高，在 32px 栏里上下各留 2px；抬高面 + 浮雕 + 按下反馈。顶栏里所有的键都改用它——返回箭头、对练页 wire、电键页「清屏」「手法」、手法页「清除」、配网页「保存」「清空」。全工程的可点元素只讲一种话。

按下反馈得自己挂事件：ui_chip 是 label 不是 lv_btn，拿不到 LV_STATE_PRESSED 的样式。像素实测按下时 y=2 由键面变成 #9C8D6A（暗线翻到顶上）、面色塌成 #E6DAC5。

顺带修掉一个先前就存在的坑：那几个顶栏 ui_button 全被写死成高 24，比 26 的行高还矮——内容比容器高，LVGL 会当溢出处理，文字下偏还会打开滚动。ui_common.c 里返回箭头那段注释警告过同一件事，但没人回头检查别处。

第五轮：深度要编码信息，不是拿来装饰

对练页改成三档深度，各自说一件事：井（凹）装内容、状态带（平）是页面本身、电键桨（凸）可以按。上一版是反的——状态带被做成了凹槽，而真正装内容的收报区却和页面一样平，深度没有编码任何信息。像素实测：y=32 井的上沿暗线 #9C8D6A → y=33..127 井面 #E6DAC5 → y=128..152 纸底带噪点纹理 → y=160+ 黄铜。

呼号不再套容器。它先是「黑底白字」（上一版高对比主题的遗留），我改成过凹陷的一枚戳——两个都不对，而且错在同一处：容器本身就是错的选择。工艺规则里分组的次序是「留白 > 分割线 > 容器」，容器是最后一档，我却一上来就用了它；而日志区一屏七八条记录就是七八个视觉噪点。更要命的是，在这套语言里凹陷/凸起编码的是「能不能按」，呼号根本不可点，给它浮雕是在撒谎。现在靠字色分主次：呼号主文墨（井上 11.64:1），报文次要墨（4.65:1），每行呼号的左边缘天然对齐，那条对齐边就是扫读用的栏——电报底稿本来就是这么排的。

电键桨上的「点」「划」改成图形。两个理由：字号受字体限制（font20 行高 26，塞不出一个够大的点），而图形想多大有多大；更重要的是 点划长度比 1:3 是莫尔斯的定义本身，画出来就把这条规则摆在了桨上，而两个汉字一点都不携带这个信息——这台机器是训练器，桨面本来就该是教材。颜色跟着按下态翻：常态刻在铜面上 7.11:1，按下时铜面被 recolor 压到 #845E29，刻痕会掉到 3.13:1 发灰，所以翻成纸色（4.77:1）。

工具链的一个洞：check_charset.py 扫 main/** 全部文件，开发专用的文件也能撑大发布版字库——实测 screenshot.c 里一句中文调试 printf 就让自检报错、逼着往字库里加字。已排除 screenshot.c / ui_probe.c，并把那句 printf 改成 ASCII（串口诊断本来也不该用中文）。

第六轮：ui_bevel 的两个后续 bug

1. 浮雕的子对象会被父容器当成布局成员。对练页的收报井是 flex 容器，那个子对象被排成了第一个 flex item，它的下沿亮线就露在第一条消息上面，看着像凭空多了一条白线。加 LV_OBJ_FLAG_FLOATING——它同时解决两件事：不参与布局，且不跟随父对象滚动（浮雕是画在井壁上的，不该跟着内容滚走）。

2. padding 不对称时下沿画不出来。收报井 pad_top=2 而 pad_bottom=0，而 transform_* 只能对称扩张，下沿的亮线被推到盒子外面。我当初把「要求 padding 对称」写成注释当免责声明，而不是去解决它——那条注释后来就成了这个 bug 的温床。现在用 translate_* 抵消不对称：transform = 边框 + 两侧 padding 均值，translate = (后侧 - 前侧) / 2。像素实测井上沿 #9C8D6A → 井面 #E6DAC5 → 下沿 #FFFAF6，完整凹槽。

第七轮：电键页与对练页统一版式

两个页面铺的是同一组电键，用户在它们之间来回切，版式不一致就得重新找一遍东西在哪。现在都是 凹陷的内容井 + 平的信息条 + 凸起的电键，像素实测两页完全一致：暗线 y=32 → 井面 33..122 → 亮线 y=123 → 信息条 124..155 → 桨 y=156。

电键页原来是「裸标签 + 点划行 + 桨」，解码文本直接摊在页面上，没有井。改造顺带把纵向预算从手算改成了共享常量：井吃掉 UI_PADDLE_H 和 UI_BAND_H 之外的全部高度，两页不再各写各的。

信息条高度提到 32 并进了 ui_theme.h（原来对练页自己写死 28）：与顶栏、提示条同在 8px 网格上，且 >= UI_FONT_CN 的行高 26。文字改居中——它是一行状态提示，不是要从左边读起的正文，而且下面就是左右对称的两块桨，左对齐会把整页重心拉偏。

第八轮：内容井要缩进才看得出是井

反馈是「报文区不够下沉，想给左右加竖边框」。量下来左右两条边其实一直画着，只是都看不见：左边那条落在 x=0——屏幕最边缘，读起来是「屏幕边框」而不是「井壁」；右边那条落在 x=319，还被宽 4px 的滚动条整条盖住了。

所以不是加边框，是把井从页面边缘缩进来（UI_WELL_INSET = 6），两侧各露一条纸底，边线才有参照物可以「相对于它凹进去」。滚动条同时往里挪 2px 让开边线。像素实测：x=0..5 纸底 → x=6 暗线 → 井面 → x=313 亮线 → x=314..319 纸底，两个页面完全一致。

电键桨不跟着缩：它们是手指要按的地方，宽度就是触控面积，而且在层次上属于「页面之下的器件」，本来就该顶满。UI_WELL_INSET 取 6 而不是 8：8 会把本来就紧张的横向内容再挤掉 4px，而这条纸底只要看得见就够了，不承担分组任务。
